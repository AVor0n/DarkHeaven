## 3. Движок

### 3.1. Модель «ожидающих решений»

Партия — это генератор, который выполняет правила и останавливается, когда
нужен выбор игрока:

```ts
type Decision =
  | { kind: 'placeStart'; prisoner; cells }
  | { kind: 'chooseAction'; prisoner; moves; canStay; canDash; keyTransfers; canEndTurn }
  | { kind: 'placeTile'; prisoner; tile; options: { cell; rotations }[] }
  | { kind: 'dodge'; prisoner; hit }
  | { kind: 'fallLine'; prisoner; options }
  | { kind: 'landingCell'; prisoner; cells }
  | { kind: 'forcedMove'; prisoner; options }
  | { kind: 'stayReplace'; prisoner; monster; cells }
  | { kind: 'lastFlicker'; prisoner; cells; canKeepFlame }
  | ...                     // расширения: позиция Плакальщика, цель пожирателя света

class Game {
  constructor(config: GameConfig, seed: string)
  readonly state: GameState        // снимок для отрисовки (только чтение)
  readonly pending: Decision | null
  readonly actions: Action[]       // всё, что сделали игроки
  readonly events: GameEvent[]     // что произошло (для анимаций и журнала)
  apply(action: Action): ApplyResult   // проверка допустимости и продолжение
  static replay(config, seed, actions): Game
}
```

- Единственный источник случайности — перемешивание запаса при подготовке
  (seeded PRNG sfc32 от хэша строки seed). `Math.random` и время в движке запрещены.
- Сохранение = `{version, config, seed, actions}`. Загрузка = повтор действий.
  Партия на ~300 действий проигрывается за миллисекунды.
- Каждое решение содержит список допустимых вариантов. UI не вычисляет правила
  сам, а только показывает варианты и превью.
- События (`moved`, `tilePlaced`, `crumbled`, `fell`, `attack`, `hit`,
  `discardedFromPile`, `extinguished`, `relit`, `keyTaken`, `lastFlickerStarted`,
  `won`, `lost` и т.д.) — основа анимаций, журнала и звука.

### 3.2. Превью

`preview(state, action)` разрешает перемещение на копии поля без вытягивания
плиток: обрушение, провокация, атаки и цепочки, кто пострадает, сколько уйдёт из
запаса, падения, ключи, повторное зажигание. Если ход ведёт в неизвестность
(вход в пустую клетку), превью так и говорит.

### 3.3. Инварианты (проверяются в тестах на каждом шаге)

- Сумма плиток на поле, в запасе, в сбросе и отложенных постоянна.
- В клетке не больше одной плитки; узники не делят клетку, кроме врат.
- Решимость 0–2; ключей у узника 0–1; ключей у узников не больше взятых.
- Все плитки на поле освещены (кроме хранителей ключей и ямы Плакальщика).
- Партия всегда либо ждёт решения, либо окончена.

## 4. Тесты

- **Юнит**: соединения, освещение, линии видимости с переносом через край,
  провокация, цепочки, падения, последнее мерцание, условия поражения.
- **Сценарии из правил**: каждый пример-иллюстрация из правил воспроизводится
  ASCII-картой поля, например:

  ```
  . ┼ . .
  . W ─ R      W — пожиратель воска, R — красный узник
  . │ . .
  ```
- **Фаззинг**: бот выбирает случайные допустимые действия, 2000+ партий на разных
  seed и конфигурациях; проверяются инварианты и отсутствие исключений.
- **Реплеи**: повтор действий даёт тот же снимок состояния.
- **E2E (Playwright)**: создать партию, сделать несколько ходов, сохранить,
  перезагрузить, продолжить.

## 5. CI/CD

- На каждый PR: `pnpm install`, Biome, `tsc --noEmit`, Vitest, сборка, Playwright.
- На `main`: сборка и публикация `apps/web/dist` на GitHub Pages
  (`base: '/DarkHeaven/'`, маршрутизация через hash).

## 6. Онлайн (этап 2)

- Авторитетный сервер держит `Game` каждой комнаты и рассылает клиентам
  снимок без порядка запаса (только размер) плюс новые события.
- Клиент отправляет действие; сервер проверяет, что оно от игрока, управляющего
  узником из `pending`, применяет и рассылает.
- Комнаты по ссылке с кодом, без аккаунтов: имя и цвет, токен переподключения
  в `localStorage`, зрители, хост может пересадить отключившегося.
- Простой чат и «пинг» клетки; опция «мрачная тишина».
- Хостинг: нужен WebSocket-сервер. Предпочтительно Cloudflare Workers + Durable
  Objects (комната = объект), альтернатива — Fly.io. Требует аккаунта Андрея.

## 7. Безопасность и ключи

- Ключи API (kie.ai) используются только в скриптах генерации ассетов,
  берутся из переменных окружения и никогда не попадают в репозиторий и в бандл.
- Оригинальные сканы не коммитятся.
